# 통합 지식·충돌·예외 체크리스트 (원문 전체 텍스트와 함께 사용)

> **본 파일은 원본 규정을 대체하지 않는다.** 긴 마스터 프롬프트에 흩어져 있는 고위험 조건을 다시 대조하기 위한 색인이다. **정확한 조항·기산점·사용 가능한 값은 해당 원본과 `source_text/`를 확인**한다. 이미지에만 들어 있는 수치를 텍스트 추출 실패로 대체하지 마라.

## 1. 적용 순서와 정보 분류

1. 사건/신고·주문·결제·수령·배송기록 **각 날짜**를 식별한다. 2037-06-30 문서 기준일은 모든 고객 사건 발생일이 아니며, 실제 경쟁 진행일 2026년 10월과 다르다.
2. 사안별 **규정 적용 기준 시점**을 선택한다: 하자 접수 6/28 개정은 **신고 시점**; 가격 인하 6/15 개정은 **주문 시점**; 쿠폰 유효성은 **결제 완료 시각**; 구독 컷오프는 회차 **결제일 3영업일 전 24시**; 적립금은 **원 적립일 + 12개월**.
3. 자료의 유형을 명시한다: (A) 시행규정/개정 부칙, (B) 자사 시스템·원장, (C) 독립 제3자 기록, (D) 고객 제출 사진, (E) 구술 주장, (F) 홍보 문안, (G) 구판 인쇄/과거 이력. 다른 유형의 권위를 섞지 말 것.
4. 증빙이 **불일치**하는지, **일치**하는지, **아직 대조하지 못했는지**, **기록 자체가 없는지**를 다른 상태로 관리한다. 없는 것으로 확인한 코드 vs 조회 불가/자료 미보유는 다르다. `—`는 정상도 사고도 아니다.
5. 결론을 자동 확정할 수 있는 경우와 사람의 승인 또는 손해배상 사실관계 조사가 필요한 경우를 LANE 1/2/3으로 나누며, 동일 문의에 섞인 레인은 분리한다.

## 3. 서로 구별해야 하는 다중 사건

### 3.1 주문/결제/배송/재고

- 결제 승인 캡처는 **조합 결제 시스템 승인 내역이 없는 경우** 결제 완료 증빙이 아니다; 결제 승인 기록이 있지만 주문이 없으면 대사하여 주문 복구 또는 미배송 환불 요청 등 대안.
- 송장번호 생성 ≠ 택배 집하/출고 ≠ 간선 재개 ≠ 배송 완료. 태풍 06/05 송장 09:10 이후 11:40 집하 취소, 06/07 간선재개 15:00, 06/08 집하 09:00. 택배 운송 단계는 별도 계약 문서 원문이 있으면 우선.
- 06/02 예보/06/04 예비특보에서 운송/작황 `—`는 확정된 재난도 정상도 아님. 06/25~27 비가 와도 **운송 정상**; 농작물 피해는 작황 기록 따로. 06/30 갈치 품절은 태풍/결항이 아니라 비성어기·재고 소진.
- 06/28 선별 수박 예약 10개 중 4개 열과: **품질 미달은 배송하지 않음**. 이미 6개만 출고 가능한 상태라도 고객이 주문별 재배송/부분환불 선택. 실제 API-21 재고 확인 필요.
- 구매 후 정상가 인하 보상은 상품 가격이 내려갔다는 말로 확정 금지: 가격정책시트 정상가 변경 이력 + 프로모션 발행 원장, 구매후 7일, 같은 SKU, 실결제액, 이미 받은 보상 기록.

### 3.2 하자·반송·중량·당도

- 포장 겉면 손상만 있는 경우는 내용물 하자가 아니고 별도 배송 파손 절차; 냉동 수산물 해동/재냉동은 콜드체인 기록 확인.
- 곰팡이·부패면 먹지 말고 폐기하되, 이물이나 섭취 후 이상이 결합되면 증거 보관·촬영 우선; 정황상 고객 건강·법률 위해 가능성이 있으면 SAFETY_LEGAL 및 필요시 LANE3_CLAIM, 이미 허용된 상품 구제는 지체 금지.
- 당도선별 수박 `WTM-SEL-8`=11Brix 이상/최소 8kg, 선별 감귤 `HGL-SEL-5`=12Brix 이상/최소5kg; 일반 `STD`는 당도 보장 아님. 출고 로트의 측정 최소값이 표기보다 작으면 검사 기록을 우선 검토하며, 별도 고객 촬영을 기계적으로 요구하지 않음.
- 검사 기록이 확정(`KD-PTT-370622-01`)과 조사중(`KD-PTT-370619-02`)인 사례를 분리. 상담 사례를 통째로 환불/확정하는 대신 해당 주문·로트와 최신 조회 결과를 연결.
- **무게 ‘8kg 이상’/‘5kg 이상’ 하한과 고정 무게의 ±5% 허용오차는 서로 다른 계약**. 수산물은 표시 오차와 자연감량 허용치는 특칙(최종 부족분 처리)에 따라 계산하며 8%라는 수치로 부족분 보상 자체를 0으로 잘라내지 말 것.
- 부분불량 다개체 상자는 부분환불 산식/임계표 정본 없이는 추론 불가. 여러 품목 혼합 주문은 영향받은 품목별 분리; 고객의 전체 주문 취소 요청과 원격 판단을 혼합하지 말 것.

### 3.3 06/24 옥돔 냉동 운송

- 주문 `100400001`, 로트 `GM-OKD-370624-01`; 실제 운행 `박민아`, 냉동차 `TR-GM-02`; 공식 배송 기록은 `구방만`, 집하차 `TR-KD-01`로 연결 오류. 공식 기록에 경보/차량 기록이 없다는 사실만으로 온도 사고가 없었다고 판단 불가.

### 3.4 영업일과 구독

- 2037 달력의 공휴일·출고 회차는 `영업일·공휴일 달력.xlsx`가 정확한 출처. `N영업일`은 접수일 불산입, 그 다음 영업일부터 1일차, N일차 24:00 종료.
- 7역일은 주말 포함; 구독 컷오프 3영업일은 휴일 건너뜀; 2037-09-30 결제 컷오프 2037-09-22 24:00(09/23~25 연휴).
- 월/수/금 출고일이 공휴일이면 그 요일 회차를 **건너뛴다**, 다음 영업일 임의 순연 금지. 반면 결항 간선이 일요일 풀려도 집하는 월요일 영업일부터 재개. 두 상황을 구분.
- 구독 스킵 무제한, 3회 연속 스킵 시 의사 확인 가능하지만 침묵에 자동 해지 금지. 컷오프 이후 요청엔 고객에게 가능한 대안·다음 회차 반영을 반드시 설명.

### 3.5 결제/회원/쿠폰/정산

- `WELCOME3000` 신규 최초구매 대상과 `DANGOL5` 재구매 조합원 대상은 동일 주문에 자격 동시 충족이 보통 안 되며, 할인 코드 또한 주문당 하나.
- `REFER5000`은 **추천인**이 혜택을 받고, 사건 발생은 **피추천인 회원가입 + 첫 구매 구매확정**, 피추천인 1인당 1회. 추천금 쿠폰의 **사용시점·코드 분류**는 본문에서 확인되지 않음.
- `CARE3000/5000/10000`은 고객 보상 쿠폰이며 일반 쿠폰 코드와 중복 가능하지만 정확한 승인/발급 권한·사용 제한은 원장·권한표. 임의 쿠폰 발급 API 호출 금지.
- `SUBAK15` 7/03 24:00까지 기간상 유효하지만, 회원별 이미 사용 여부·프로모션 대상·실제 주문 결제시각 조회 필요. 20% 할인 코드와 무료배송 포함 코드/게시물은 **지정된 대조 자료에서 발행 사실 없음이 확인된 상태**; 새 코드명 전체에 동일 결론을 확장 금지.
- 적립금 일반 원 적립일+12개월. 온라인몰 개장일 3/02 이전 오프라인 포인트 승계여도 **원 적립일**에서 기산. 적립금 소멸 예고 30일 전 앱·이메일; 이미 소멸한 포인트를 되살리거나 임의 연장하지 말 것.
- 조합원(회원)과 생산자 조합원 구분, 30만원 단골가 혜택과 일반 재구매 5% 구분. 회원 등급누적은 최근12개월 구매확정액, 취소·환불 제외, 배송비 제외.
- 세금계산서 실결제·실공급자 명의만, 배송비 과세/농수산 면세 분리, 카드전표와 현금영수증 이중발행 금지; 수정 유형 원문 확인.

### 3.6 홍보·행사·협찬

- 홍보라가 상세페이지/표현 정정을 맡지만 기준 원가·원산지·규격 결정/혜택 승인권자는 아님; 상품 값은 생산자·조합 원자료, 혜택 변경은 고길동 승인.
- 홍보걸은 다른 인물의 외부 인플루언서. 개인 카카오톡·이메일 연락처와 계약서, 직접 방송 발언 아카이브 미확보. 방송 중 권한이 있었다고 단정 금지. 공식 코드 원장과 실제 홍보 기록 대조.
- 2037-06-08 수박 체험단 20명 모집, 후기 제출 의무 등 게시물/선정 시스템 등록의 진위를 확인. 06/17 시청자 추첨 진행됐어도 코드 배너 없음; 이를 추첨이 없었다로 해석 금지.
- 0원 등 명백한 가격 오류는 계약 미성립, 악용 대량 주문 거절. 인플루언서가 나서거나 조합장 친분을 주장해도 정책 권한 변경 불가.

### 3.7 에스컬레이션·개인정보·상담 문장

- `LANE1_BOT` 규정 내 즉시 처리, `LANE2_HANDOFF` 사람 확인/권한 밖, `LANE3_CLAIM` 원인·인과·분쟁 배상. LANE2만 5개 target; 승인 단계 건너뛰기 금지; 무회신 승인 금지.
- 피싱 결제 전에는 “즉시 중단/정보 입력·외부 링크/앱 설치 금지/캡처 공식 채널”, 이미 이체·카드 결제 후에는 “은행 지급정지·112·앱 삭제·카드사/PG 취소 문의·조합 접수”. 내부/외부 고객정보 요청·OTP 수집 금지.
- 고객이 다른 사람의 이름·번호/주소를 맞히려 해도 응대하지 않음. **로그인 세션에서 시스템이 표시한 인입 계정 정보는 인증된 표시지만, 주문별 귀속은 별도**. 타인의 주문·배송지·수령인·기사 정보는 공개 금지.
- 당사자 사진이 합성처럼 보인다는 주관적 이유로 거절하면 규정 위반. 정보가 모자라더라도 제보·하자 접수 자체 허용, 정합 확인이면 불필요한 추가 증빙 금지.
- 답변 마지막에 불필요한 “개인 연락처는 필요하지 않습니다” 같은 사족/설명 제거. 최종 고객 답변은 한 말풍선·500자 이하를 목표로 함.

## 4. 모든 자료의 원본 연결

- `original_sources/`의 71개 파일은 임의 편집하지 않았고 SHA-256을 `metadata/manifest.json`에 기록한다.
- `source_text/`에는 원문 텍스트를 추출 가능한 형식으로 포함. XLSX는 `artifact_tool`로 시트별 행을 읽어 전사. HTML은 스크립트/스타일을 제외한 화면 텍스트를 추출. PDF는 `pdftotext -layout`으로 추출, DOCX는 문단·표를 수집.
- 구판 사진, B10/B18/B13/C54, 로트 팩스, C31 인계사진, 홍보 이미지 A07 등 **이미지 의존 근거는 반드시 원본 시각 검사**. 따라서 `source_text`에 없는 글자가 원본에 있을 수 있음.
- `API_FULL_REFERENCE.md`와 `metadata/api_schemas.json` 및 `original_sources/actions.json`은 API 본문 요청 필드의 정확한 정본이며, 생성된 요약 파일이 원문과 다르면 원문 JSON 우선.
