# 완료하지 못한 항목 · 미확보 자료 · 가정

## A. 이 환경에서 검증하지 못한 것(사용자 환경에서 확인 필요)

1. **실제 Action API 호출** — 토큰·공개 TC ID가 없어 가짜 서버(`tests/fakes.py`)로만 검증했다. 실제 응답 필드는 actions.json 스키마와 같다고 가정.
2. **실제 LLM 품질·지연** — GPU가 없어 스크립트형 가짜 LLM으로 루프·가드만 검증했다. 정책 판단의 정확도는 Qwen 실측이 필요하다.
3. **평가 대화 형식** — TC ID와 인입 계정이 대화에 어떤 표기로 오는지 문서에 없다. 파서(여러 표기) + LLM 보조 도구(`set_test_case_id`, `register_inbound_account`) + 설정(`INBOUND_MARKER_REGEX`, `AUTH_MODE`)으로 대비했다.
4. **에스컬레이션 `lane` 값 형식** — 스키마는 문자열뿐이다. 기본값은 `LANE2_HANDOFF`/`LANE3_CLAIM`, 이관 대상·우선순위는 reason 앞머리 `[SECURITY][긴급]`. 다르면 `ESCALATION_LANE_FORMAT`으로 조정.
5. **API-38 `trigger` 값** — 자유 문자열이며 허용값 목록이 없다. LLM이 사유를 짧게 적는다.
6. **카카오 웹훅 실제 필드명** — 기존 코드의 후보 경로 탐색 방식을 유지(content/text/utterance…, botUserKey/userKey…).

## B. 원문이 없어 코드화하지 않은 정책(추정 금지)

| 부분환불 산식·박스 비율 임계표 | 다개체 일부 불량 비율 계산 없음 → 재배송/전액 선택지 또는 LANE2(OPS) |
| 프로모션 마스터 전체 | API-20 단건 조회로만 판단, 404면 '발행 기록 확인되지 않음' |

## C. 설계상 선택(근거)

- **엄격 인증 기본값**: 조합 규정 제8조·개인정보 처리방침 제12조 — 인입 계정 + 주문 귀속 확인 없이 주문 상세·처리 불가.
- **저장 주소·연락처·수령인 정보는 LLM에도 주지 않음**: 저장정보 선낭독 금지(처리방침 제9조), 수령인 보호(규정 제12조). 주소 확인은 `compare_order_address`로 대조만.
- **5만원 초과 부분환불 차단**: 권한 위임표 제4조①. 주문 전액·품목 전액(하자 전액환불·규정상 반환)은 예외로 통과.
- **같은 대상 재접수 차단**: 서버가 마지막 본문으로 덮어쓰므로, 한 상담에서 같은 대상 접수는 기존 접수번호로 안내.

## D. 남은 개선 여지(시간 제약으로 미구현)

- 다중 요청 DAG를 코드로 분해하는 별도 플래너(현재는 LLM이 병렬 도구 호출로 처리).
- 규정 전체를 Rule 객체로 기계화한 근거 인덱스(현재는 프롬프트 요약 + 결정적 계산기).
- GPU 온도·큐 길이 모니터링(현재 `/health`는 지연·콜백 성공률·API 호출 수).
